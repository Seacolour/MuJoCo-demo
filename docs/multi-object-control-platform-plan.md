# 多物体机械臂 Agent 遥控平台实施计划

## 目标与边界

用户在浏览器中持续输入自然语言指令，例如“把绿色方块放到蓝色区域”。同一个 MuJoCo 窗口持续展示 xArm7 的动作；平台展示场景、任务队列、阶段反馈、取消和验收结果。第一版使用仿真真值识别物体颜色与位置，不宣称视觉感知或真机控制。

当前已实现双方块、三区域的物理抓取，六种单任务组合均通过验收。ROS 2 桥接节点在 `--multi` 模式下持续持有同一仿真场景与 Viewer；DeepSeek、浏览器遥控台、场景快照和连续任务已实测联通。任务队列目前由桥接节点持有，浏览器任务记录保存在平台进程内。

## 目标架构

```text
浏览器遥控台 --HTTP 指令/取消--> 平台服务 --ROS 2 任务--> 仿真执行进程
      ^                            |                         |
      +-----SSE 阶段与结果----------+                         +--持久 MuJoCo 场景与 Viewer
                                   +--DeepSeek 任务解析
                                   +--任务队列、事件记录、场景版本
```

目标架构由平台服务拥有任务记录与调度顺序；仿真进程独占 `MjModel`、`MjData` 和机器人控制，只执行当前任务。目前桥接节点仍持有执行队列，平台服务负责提交与展示。DeepSeek 只选择已知物体与目标区，不生成坐标、关节角或执行代码。ROS 2 初期沿用现有 Topic 协议；任务语义稳定后可改为自定义 Action。

## 数据与任务约定

- 场景目录包含 `red_cube`、`green_cube` 和 `red_zone`、`green_zone`、`blue_zone`，分别记录颜色、MuJoCo body/geom/site 名称、几何尺寸和当前位置。两块方块初始位置与目标区分开。
- 一条用户指令先生成一个 `PickPlaceTask(object_name, target_name)`；不存在、歧义或已占用的目标区在运动前拒绝。
- 每个任务包含请求 ID、原始指令、解析结果、场景版本、状态、阶段记录和验收结果。状态流为 `received → parsing → validated → queued → executing → verifying → succeeded/failed/cancelled`。
- 验收选中的方块是否被夹起并稳定落入目标区，同时检查未选中的方块没有明显位移。完成后更新场景占用与版本；下一条指令基于新状态执行。

## 实施顺序与验收

### 阶段 1：多物体仿真与通用执行器

状态：已完成。六种单任务、两条连续任务、未知对象和目标占用的验收测试已通过。

- 扩展桌面场景为两块方块、三个颜色目标区；先检查五个位置的 IK 可达性、夹爪间距和运动碰撞。
- 从任务中的物体与目标 ID 查找模型实体，移除执行器中的 `red_cube_geom`、固定抓取高度与单一目标假设。
- 重置场景分别运行 2 × 3 共六种任务；加入未知对象、目标占用和未选中方块位移的失败测试。

完成条件：六种单任务在物理仿真中通过接触、抬升、放置和稳定性验收。

### 阶段 2：持续场景与 ROS 2 连续任务

状态：持续场景、Viewer、跨节点连续任务、队列和取消均已验证。任务队列归属调整留在平台加固阶段。

- 让仿真进程只加载一次模型并持续持有 Viewer；多个任务在同一 `MjData` 上依次执行。
- 保留请求 ID、排队、取消和阶段反馈；将任务队列最终移到平台服务，ROS 2 桥接只持有一个执行中的机器人目标。
- 连续执行“红方块到蓝区、绿方块到红区”，确认第二条任务看到第一条造成的场景变化。

完成条件：不重置场景即可连续完成两条指令；取消或执行失败不会把任务报告为成功。

### 阶段 3：Agent 解析与浏览器遥控台

状态：浏览器提交、SSE 反馈、场景占用更新、两条连续自然语言指令与已占用目标拒绝已验证。任务记录持久化和场景版本并发校验仍待实现。

- DeepSeek 的提示词来自当前场景目录，并通过结构化校验限制为可执行任务；场景版本变化后重新校验。
- 用 Python 平台服务提供提交、查询、取消、场景快照和事件流接口；浏览器界面显示指令输入、物体与目标区、队列、当前阶段、取消按钮和任务历史。
- 平台服务记录每个任务的解析、执行、验证与失败原因；浏览器刷新后能恢复任务状态。

完成条件：浏览器连续提交两条自然语言指令，页面与 MuJoCo Viewer 同步显示进度与最终结果；无效、歧义和目标占用指令会被明确拒绝。前两条连续任务与目标占用拒绝已经实测；歧义指令的多样化验收仍待补充。

### 阶段 4：平台加固

- 将调度队列移至平台服务，ROS 2 桥接只执行当前机器人目标；任务发出前核对场景版本和目标占用。
- 将任务与事件记录持久化到 SQLite，服务重启后能恢复历史，并把中断中的任务标记为可解释状态。
- 为多种歧义、重复、取消及失败场景加入回归测试；评估是否需要自定义 ROS 2 Action 代替当前 Topic 协议。

## 后续扩展

自定义 ROS 2 Action 可提供标准化的 Goal、Feedback、Result 与 Cancel。相机图像和 VLM 感知、真机驱动、端侧安全控制及多机器人调度在上述闭环稳定后单独评估。
